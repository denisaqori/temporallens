## 2. F1 implementation contract

### Training, selection and artifacts

Use D16's eight four-subject validation groups and their 28-subject training complements. Fit normalization and class weights on each training complement only. Apply D38's existing recipe unchanged: seeded PyTorch-default CNN initialization, FP32 Adam, learning rate 3e-4, coupled L2 weight decay 1e-4, betas (0.9, 0.999), epsilon 1e-8, no AMSGrad, scheduler, mixed precision or gradient clipping. Fail on non-finite loss or gradients before the update.

Train each selection fold through the accepted horizon. At each epoch, compute 18-class macro-F1 separately for the four validation subjects, using labels 0–17 and zero for undefined class F1, then average those four values equally. D18 uses a full ten-epoch trailing mean, first eligible at epoch 10, with the earliest exact tie. Save each fold's selected model for analysis, and derive the common budget B by D18's ceiling-median rule. D19's existing scratch replacement and blocking rule remain binding.

Retain immutable model snapshots for every eligible epoch until B is known. For every fold, copy the exact epoch-B parameters **and buffers**, including BatchNorm state, from the accepted horizon's trajectory to the development artifact. Do not silently use the nearest saved epoch. Keep all three artifact roles distinct:

| Artifact | Source | Use |
|---|---|---|
| `folds/fold{k}/best.pt` | That fold's individual smoothed peak | Existing selected-fold validation, extended test analysis and D10 |
| `development/fold{k}/fixed_budget.pt` | That accepted selection trajectory at the shared B | F1 refit-temperature fitting; shared G2/G3/G4 development infrastructure; matching language development encoders under D67 |
| `refit.pt` | A fresh fit on all 32 development subjects for B | Canonical final F1 and downstream final experiments |

These paths sit under the existing F1 root for reportable CUDA artifacts; D47 requires a separate preliminary root. If a fold's individual peak happens to equal B, the model states may coincide, but the two artifact roles and their provenance remain explicit. Once B is frozen, retain the eight development models and eight analysis models; only superseded intermediate snapshots may be pruned. Before a D19 replacement cost, this is eight selection fits plus one refit, not seventeen fits. It is not a measured runtime estimate.

### Reuse invariants and failure behavior

The first B epochs must implement the same fitting procedure regardless of the announced horizon or validation results. Keep training data/order, initialization rules, preprocessing, class weights, precision and optimizer mechanics fixed. Validation must not update parameters or buffers, alter subsequent training random streams, or leave the model in the wrong mode. A separate evaluation generator can prevent iterator creation from consuming training RNG; isolate or restore all relevant CPU/device RNG state rather than relying only on `shuffle=False`. Bitwise equality is not promised across devices or nondeterministic kernels, but validation-dependent training behavior is not permitted. See [PyTorch reproducibility](https://docs.pytorch.org/docs/stable/notes/randomness.html).

Every retained model records its source run, fold, epoch B, accepted horizon, source snapshot digest, manifest/config identities, training/query subjects, normalization and class-weight digests, training RNG provenance and device. The persisted development artifact has its own digest; metadata changes need not preserve the source file's byte digest, but must preserve the copied model state. Consumers verify these identities and the generator's exact parent encoder, not just dimensions or paths. Missing or incompatible exact-B snapshots block artifact creation. Any recovery rebuild must be explicit, recorded and validated against the frozen recipe, never a silent replacement or a chance to change B.

The `{model_state, model_config}` inference/checkpoint contract remains unchanged. Do not add optimizer state as an extra top-level key to these artifacts. A future resumable training-state artifact would be separate; resuming Adam requires optimizer state as well as weights, but this package does **not** change D19 to resume. See [PyTorch checkpoint guidance](https://docs.pytorch.org/tutorials/beginner/saving_loading_models.html).

### Calibration and interpretation

Fit the refit's single temperature from pooled held-out-subject logits produced by the eight exact-B development models. D33/D39 remain unchanged: ordinary NLL, no class weighting, equal subject weight, equal repeat weight within subject, natural class proportions and equal window weight within each repeat; use the declared float64 inverse-temperature solver and boundary failure checks. Store T and fitting provenance in the matching refit's `model_config` and freeze before final inference.

D40 continues to use each individually selected analysis model for leave-one-validation-subject-out temperature diagnostics. Its temperatures never replace the refit's pooled exact-B estimator. G2/G3/G4 reuse the same development encoders; fold-local generator fitting, its budget and parent-encoder identity are unchanged. Do not conflate generator training with the eight encoder fits removed by D48.

The global B used every development fold, so these development procedures remain conditional on selection, not unbiased nested CV. Fresh retraining on the same subjects would not remove that dependence. Using a tuning-validation set for temperature fitting is compatible with the calibration procedure in [Guo et al., §4](https://proceedings.mlr.press/v70/guo17a/guo17a.pdf); fitting scores are still not independent evaluation. The complement-28 temperature-to-all-32-refit transfer remains an acknowledged approximation.

## 3. Approved language aggregation and existing constraints

At each shared nominal checkpoint time t, compute each query subject's 18-class macro-F1, average the four subjects in each fold, then average the eight folds. With equal fold sizes this is the mean of 32 equally weighted subject scores. Locate the unsmoothed peak **after aggregation** on D63's fixed checkpoint grid with D61's earliest-eligible exact tie rule. Do not take the median of the eight peak times. This D49 choice optimizes the observed common-budget mean curve; it does not guarantee the best unseen-subject performance.

D66/D67 apply this aggregation separately to each arm and each reporting index 0–2, giving one language B per arm/seed under the same maximum horizon and selection rule. D64 separately fixes the shared ten-epoch maximum; D70 settles RNG identities below; D71/D72 fix numerical execution; D73 fixes batch/accumulation boundaries; implementation remains open. D55 separately fixes the initial LR grid and arm-level selection policy. Do not apply D49 to F1, which keeps its median rule.

**Equal epochs, with optimizer steps reported (D50).** One language epoch is one pass through the current fit's eligible training windows. Transfer the selected nominal B epochs from fold training to the all-32 refit as B epochs, not the same number of optimizer updates. This preserves approximate exposure per example and deliberately allows greater optimizer exposure in the larger refit. With similar per-subject window counts the refit makes about 32/28 = 1.143 times as many updates, but actual counts depend on window counts, batching and accumulation tails. At every selection checkpoint and retained development/refit artifact, report nominal epoch target, actual consumed training-window count/epoch position and cumulative completed optimizer updates. Record the fitting-window count, batch size, accumulation factor and final-partial-batch/accumulation policy; microbatches are not optimizer steps. D63 supplies fractional-target mapping below, completed by D73's natural tail and endpoint rules. This decision does not choose the numeric horizon or change F1.

**Adam identity only (D51).** The owner chose to stay with Adam for L2/L3/L4 after discussing AdamW. Use coupled L2 rather than decoupled weight decay. Do not silently inherit F1's other numeric settings: D52–D73 explicitly settle the language optimizer, LR pilot and numerical/batch rules. D52–D54 separately fix the coefficient, groups and Adam mechanics below; D55 fixes the initial LR grid and selection policy. The optimizer touches only the trainable projector/head (head only in L4), never the frozen CNN or language backbone. The choice does not assert performance superiority over AdamW or reopen F1.

**Fixed coupled-L2 coefficient (D52).** The owner approved `1e-4` across L2/L3/L4. Encode it as `training.weight_decay: 0.0001` with D51's coupled-L2 mode and D53's explicit groups. Implement this penalty once through Adam's `weight_decay`; do not add a duplicate manual L2 loss. This is a fixed reference value, not a selected optimum or an equivalent AdamW strength. Frozen backbones are excluded in every case. F1 remains unchanged.

**Weight matrices only (D53).** Assign `1e-4` to trainable weight matrices in the projector/head, and `0.0` to trainable biases and normalization parameters. L4 contributes only head parameters. Classify normalization parameters by owning module before tensor shape, so a multidimensional normalization scale cannot accidentally enter the regularized group. Exclude frozen parameters from the optimizer entirely. Require complete, disjoint membership by parameter identity; unknown trainable roles block training. Record every group's names, shapes and coefficient. The later grouping tests must include biases, a multidimensional normalization parameter, frozen weights and duplicate/unclassified cases. This changes no F1 settings.

**Adam mechanics and no scheduler (D54).** The owner approved betas `(0.9, 0.999)`, epsilon `1e-8`, `amsgrad: false` and a constant LR throughout each fit, with no warmup, decay or validation-driven schedule. D55 separately fixes the initial LR grid and selection policy below; no value has yet been selected. These settings are explicit reference choices, not tuned optima. Constant LR removes one source of horizon dependence, but does not replace the checkpoint-reuse invariants. D72/D73 settle precision, gradient and batch declarations; the overall implementation gate remains closed and F1 is unchanged.

**Initial LR grid and per-arm selection (D55).** The owner approved the same initial candidates `{3e-5, 1e-4, 3e-4}` for L2/L3/L4, selecting separately for each arm using development data only, then freezing that arm's selected LR across reporting seeds and their refits. Do not reselect LR for each reporting seed or force equal winners across arms. The existing `training.learning_rate: 0.0001` remains an unselected scaffold, never a fallback. The later runner must resolve and record the selected value and development-selection provenance before use. D56–D65 fix pilot size, fold IDs, separation from reporting, score aggregation, both tie conventions, pilot index, checkpoint evaluation, shared maximum horizon and bounded grid expansion below; D70 fixes phase/component keys/sharing below; D71/D72 fix numerical execution; D73 fixes batch/accumulation boundaries; implementation remains open. Only D65's one shared pilot expansion is permitted; freeze the arm LR after its selection lifecycle completes. This grid is an explicit reference choice, not a literature-derived optimum. The `training.learning_rate_selection` declaration is ready; the overall implementation gate remains closed and F1 is unchanged.

**Peak-of-mean pilot LR score (D59).** For each arm/LR at every common nominal checkpoint time, compute each query subject's 18-class macro-F1 using labels 0–17 including rest and undefined class F1 = 0.0. **Exact LR-score ties (D60).** The owner approved exact comparison of unrounded candidate scores, with no near-tie tolerance band. This is a predeclared tie convention, not a claim of optimality or statistical equivalence. It resolves ties between candidate LRs; D61 separately fixes checkpoint-time ties below.
